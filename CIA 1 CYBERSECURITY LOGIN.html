01

The access rule

Two rules run the whole engine. Everything else on this page is either proving them or stress-testing them.

Lockout rule
F → S
Three consecutive password misses trip the lock — automatically, no human in the loop.
Access rule
L ↔ ( P ∧ Q ∧ R ∧ ~S )
Access is granted if and only if the password is correct, the OTP is verified, the device is trusted, and the account is not locked. All four conditions are jointly required — this is a strict conjunction, not "any two of four."
Denial rule (De Morgan form)
~L ↔ ( ~P ∨ ~Q ∨ ~R ∨ S )
The same rule, read from the failure side: any single condition dropping out is enough to fail the whole gate.

03

Worked proofs

The same three inference steps from the pipeline above, written out formally.

Step 1 · Modus Ponens — deriving the lockout
Premise 1 F → S
Premise 2 F (password failed 3 times — observed)
Conclusion ∴ S — the account is locked
Step 2 · Disjunctive Syllogism — denial from the De Morgan form
Premise 1 ~L ↔ (~P ∨ ~Q ∨ ~R ∨ S)
Premise 2 S (from Step 1)
Conclusion ∴ ~L — access denied, regardless of P, Q, or R
Step 3 · Hypothetical Syllogism — chaining the two rules
Premise 1 F → S
Premise 2 S → ~L
Conclusion ∴ F → ~L — three failed passwords guarantee denial, transitively, without re-checking S by hand
04

What we'd harden next

The current rule is binary and permanent: three strikes locks the account with no decay and no extra signal. Four upgrades close real gaps without adding friction for a legitimate user.

Signal

Add a risk proposition, B

B = "login attempt matches the user's normal behavior" (location, time of day, IP reputation). A password can be correct and the attempt still be suspicious — B lets the gate see that.

Decay

Replace permanent S with timed lock, S(t)

Instead of S staying true forever, define S(t) = true only while t < lock_time + cooldown. The proposition becomes false automatically after, say, 15 minutes.

Escalation

Exponential backoff on F

Make the lockout duration a function of repeated F events: 1st lock = 1 min, 2nd = 15 min, 3rd = 1 hour — punishes sustained attacks far more than a single mistyped password.

Alerting

Notify on F, not just on S

Add N = "owner notified of failed attempt." Fire N the moment F becomes true, before the account even locks, so the real owner learns about an attack in real time.

L ↔ ( P ∧ Q ∧ R ∧ B ∧ ~S(t) )
Hardened access rule — same shape, one more mandatory factor, one lock that heals itself
